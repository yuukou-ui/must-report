## 2026-08-31 清掃日が前日になる不具合（5d389ed）
- 原因1：`valueAsDate = new Date()` は日時を世界標準時として読むので、日本時間の朝9時前に開くと必ず前日になった（8:51 に起動 → 前日）。
- 原因2：日付を入れるのが起動時の1回だけで、開きっぱなしだと古い日付が残った（同じ起動のまま 10:49 に2件目 → 前日のまま）。
- 対策：`todayJST()` で日本時間の日付を文字列で作り、プレビュー表示時・PDF作成の直前・次の報告書へ・アプリに戻った時に取り直す。
- ただし清掃者が手で直した日付（前日分をあとで作る等）は書き換えない。下書きの復元も「手で直した日付」だけ戻す。

## 2026-08-27 物件一覧の受け渡し／報告書ツールのオフライン対応（238806f）
- 物件一覧は公開URLに置かない。リポジトリが公開なので、置けば誰でも読めてしまう。
  → まとめツールで `MUST-BUKKEN/1 <件数>` 付きの文字列をコピーし、LINE等で必要な人にだけ渡し、報告書ツールに貼り付ける。
  件数は、受け取った側で途中で切れていないかを確かめるため。取引先名は入れない（現場に必要なのは物件名だけ＝渡す情報を最小限に）。
- 配られた一覧は、端末が自分で覚えた履歴と混ぜない（一覧を消しても現場の履歴が消えないように）。
- オフライン対応：電波の無い建物でも入力・写真・PDF作成・保存まで通す。html2canvas・jsPDF を `lib/` に自前で置き、`sw.js` で保管。
  画面本体はネットワーク優先（作り方を誤ると「古い画面のまま更新されない」副作用が出るため）、部品・画像はキャッシュ優先。
  まとめツールは対象外（PCで使うもの・別の部品を読むので中途半端に保管すると壊れて見える）。
- 判定が微妙な似た名前は「知らせるだけ」。既定は新規登録のまま＝押さなければ何も起きない。

## 2026-08-26 番号の書き分けを統一 V=Ⅴ=五=5（132d720）
- 同じ建物が「グレース5」「グレースV」「グレースⅤ」「グレース五」と書かれる。番号らしき部分を算用数字に直して照合する。
- 英字は「ひとかたまり全部がローマ数字の時だけ」直す（ivy館・mixiビル は壊さない）。
- Ⅴ（ローマ数字の文字）は NFKC 正規化でラテン文字の V に化けるので、正規化の前に数字へ直す。
- 候補の × は指で確実に押せる大きさ（44px）にした。

## 2026-08-21 写真8枚が入らない不具合（31bd7be。発端は Galaxy A25 5G の現場報告）
- 症状：8枚選んで確定すると1枚も入らず、エラーも出ないまま元の画面に戻る。
- 原因：写真のメモリは「ファイルのMB」ではなく「横×縦×4バイト」で効く。4080×3060 の写真は 2.65MB のJPEGでも展開すると約50MB。
  旧コードは8枚を同時に展開して約400MBを一度に要求し、ブラウザが力尽きていた。
- 守るべき3点：①1枚ずつ順番に処理する ②展開する時点で縮める（`createImageBitmap` の `resizeWidth`。50MB→約6MB）③1枚につき展開は1回だけ（サムネは縮小済みの画像から作る）。
- 読めなかった写真は黙って捨てず、ファイル名つきで理由を画面に出す。
- タブが落ちても打った文字が消えないよう、入力を端末に自動で控える（写真は容量が大きいので対象外）。

## 2026-08-13〜15 LINEで送る時の title（af7913e → a4a9f8e → 85a8e3f）
- 経緯：`navigator.share` に title を渡すと、iOSではPDFの前に「ファイル名だけのメッセージ」が1通余分にLINEへ届く（Androidは title を無視するので出ない）。
  → title を外したら、iPhoneの共有シートから LINE のアイコンそのものが消えて送れなくなった。→ title を戻した。
- iPhone実機での判定結果（2026-08-15）：
  | 共有シートに渡したもの | LINEが出るか |
  |---|---|
  | PDFだけ | 出ない |
  | PDF＋title | 出る |
  | テキストだけ | 出る |
  | 画像だけ | 出る |
  | ファイルApp経由 | 出る |
- 結論：LINEの共有拡張は、ファイル単体を渡されると反応しない。テキストが1つでも含まれていれば出る。title は飾りではなく LINE を呼び出すスイッチなので、外せない。
- ユーザーの選択：PDFの前に届く1通（ファイル名）はそのまま受け入れる。送れないより実害が小さい。

## 2026-06-12〜16 報告書のレイアウトとPDFの作り方（c569980・84caaea・239afd9 ほか）
- PDFはブラウザの印刷機能を使わず、報告書を画像にして jsPDF で直接作る。印刷機能だと iOS Safari がURL・日付・ページ番号を勝手に入れ、1枚に収まらないことがあったため。
- 報告書はA4の縦横比に固定した1枚。写真は4:3固定・2列×4段で、枚数に関わらず大きさと位置を一定にする（何枚もの報告書を見比べた時にそろうように）。
- 作業内容は最初は空で、各端末で使う項目を足していく方式（削除するまで残る）。「済み」の表記はやめた。
- 項目の値は1行に固定し、長い物件名でもレイアウトが崩れないようにした。
